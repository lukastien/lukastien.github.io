01 — PROJECT OVERVIEW

The project

Sports-betting arbitrage exists when different sportsbooks price the same event inconsistently enough that the combined implied probability of all outcomes drops below 100% — letting a bettor cover every outcome and lock in a profit regardless of the result. Spotting that by hand, and sizing the stakes correctly, is tedious and error-prone.

ArbFinder is a frontend web application that automates the whole workflow: define a market with any number of outcomes, enter each sportsbook's American odds in a spreadsheet-style grid, and instantly get arbitrage detection, optimal stake allocation, ROI, and a ranking of every sportsbook combination.

Built for bettors and odds-comparison hobbyists who want correct math without a spreadsheet. There is no backend and no live odds feed: odds are entered manually, and all markets, odds, and bankroll settings persist in browser local storage. (An earlier homepage summary mentioned APIs — the shipped app does not call external APIs; this page describes what is actually implemented.)

Arbitrage math

For each outcome the best odds across books are converted to implied probability; if Σ (1 / decimal_odds) < 1, an arbitrage exists. Stakes follow stake_i = (bankroll / Σ implied) / decimal_odds_i, guaranteeing an equal payout whichever outcome wins.

Application engineering (TypeScript)

A component-based frontend (src/components/: odds table, odds heatmap, arbitrage summary, bet allocation, rankings, bankroll control, market sidebar) over a tested calculation core (src/lib/arbitrage.ts, src/lib/odds.ts) with a scripts/verify-core.mjs verification script for the math.

UX details

Inline validation catches malformed American odds (+110, −120) as you type; a colour-coded heatmap highlights best/worst odds per outcome; a bankroll slider ($100–$10,000) rescales every stake instantly; markets can be created, duplicated, renamed, and switched from the sidebar; light/dark themes are supported.

Persistence without a backend

Custom hooks (use-markets, use-local-storage) persist all state locally — zero accounts, zero server, works offline after load.

03 — CHALLENGES & DECISIONS

Challenges & decisions

Correctness of the core math

Challenge: A rounding or conversion slip silently turns 'guaranteed profit' into a guaranteed loss.

Decision: Isolate arbitrage/odds math in a pure library (src/lib/) and verify it with a dedicated script, separate from UI code.

Combinatorial ranking

Challenge: Ranking every sportsbook combination grows combinatorially with books × outcomes.

Decision: Evaluate combinations systematically and rank by ROI with expandable per-outcome stake detail, keeping the summary panel to the single best opportunity.

No live odds feed

Challenge: Real odds APIs are paywalled/rate-limited and would need a backend and keys.

Decision: Ship a manual-entry tool with strong validation and persistence instead — and describe it accurately rather than implying live data.
