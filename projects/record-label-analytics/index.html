What 100 events reveal about revenue, venues, and marketing spend

JUN 2026BY LUKAS TIEN

A SQL analytics project over 100 DJ and concert events: a SQLite database with derived profit, fill-rate, and marketing-spend metrics, analysed with CTEs and window functions to rank events, venues, and genres and to test whether marketing spend actually produces profit.

PYTHON · SQL · EXCEL · TABLEAU

01 — PROJECT OVERVIEW

The business problem

A promotions team or venue operator running many events needs to know: which events actually make money, where marketing spend is working, and which venues and genres deserve more bookings?

This project builds a SQL database of 100 DJ and concert events (Jan 2024 – Dec 2025) and answers those questions with executive KPIs, revenue and attendance analysis, marketing-channel breakdowns, and advanced SQL (CTEs, window functions, performance tiers).

Data honesty: the 100-event dataset is fictional, generated to demonstrate business-focused SQL analysis. Every figure below is computed by the queries in the repository from that dataset — the portfolio value is the analytical method, not a claim about a real label's books.

Useful to promotions, venue, and marketing teams as a reusable query library: swap in real event data and the same KPIs, tiers, and ROI views apply.

Genre performance

EDM leads revenue by event type (~$586K), followed by Hip-Hop (~$394K) and Open Format (~$306K) — while profitability still depends on budget discipline per event.

Venue scale effect

Large-capacity venues (Grand Stage, Pulse Arena) dominate top-revenue events; the top 3 events alone account for a significant share of portfolio revenue.

Marketing spend ≠ profit

Spend is balanced across TikTok (~$94K), Instagram (~$91K), flyer (~$89K), and email (~$87K), but high-spend-tier events do not always produce the highest average profit — some low-budget events with strong organic turnout outperform heavily marketed ones.

An earlier homepage summary described this work as projecting a ~15% revenue lift from reallocating outreach. That figure is a modelled projection, not a measured result, and it is not reproduced as a computed output in the repository — so it is not presented as a finding here.

Schema design

sql/schema.sql defines the events table plus enriched views with derived metrics computed in SQL: profit (revenue − budget), attendance rate, and total marketing spend across four channels.

Analytical SQL

sql/analysis.sql covers executive KPIs, top events, revenue by type/venue, fill rates, and channel spend; sql/advanced_analysis.sql adds RANK/ROW_NUMBER/LAG window functions, running revenue totals, and CASE WHEN performance tiers.

Method notes

RSVP-to-attendance conversion is used as an engagement proxy because the dataset has no customer IDs — returning-vs-new analysis is explicitly noted as impossible rather than approximated silently.

04 — CHALLENGES & DECISIONS

Challenges & decisions

No customer identity in the data

Challenge: Without customer IDs, repeat-attendance and customer-lifetime questions cannot be answered.

Decision: Use RSVP conversion as an engagement proxy and state the limitation in the README and insights — do not fabricate a retention metric.

Spend can mask weak demand

Challenge: Balanced channel budgets make 'spend more' look like a strategy even when organic events outperform.

Decision: Compare spend tiers against profit, not just revenue, leading to the recommendation to cap spend until RSVP velocity confirms demand.
